# Доступ менеджеров к базе лидов — предложение на согласование

Статус: согласовано владельцем 12.10.2026; реализовано и проверено локально.
В GitHub и production не опубликовано.

## Поведение

В «Настройки → Команда» администратор или руководитель включает и выключает
для каждого менеджера переключатель «Доступ к базе лидов».

- По умолчанию доступ выключен у всех менеджеров; у админа и руководителя он есть всегда.
- При включении менеджер видит «Базу лидов», фильтрует свободные лиды,
  открывает их карточки в режиме просмотра и может взять свободный лид себе.
- После назначения менеджер работает с лидом по существующим правилам.
  Доступ к чужим назначенным лидам и выдача лидов другим сотрудникам не открываются.
- При выключении доступ к свободной базе закрывается; уже назначенные менеджеру лиды остаются у него.
- Менять разрешение можно только сотруднику своего рабочего пространства;
  изменение записывается в журнал. Сервер проверяет разрешение на каждом запросе.

## Реализация

1. Одно разрешение `can_access_lead_pool` у пользователя и миграция `0059`
   с default false, после фактического head `0057`.
2. Защищённое изменение разрешения в модуле `users`, выдача признака в `/me`
   и списке команды. Использовать существующие зависимости admin/head.
3. Проверки чтения свободной базы, карточек и самостоятельного назначения.
   Разделить просмотр и изменение: расширение чтения не должно открыть
   редактирование, удаление, вложения, AI-действия или массовые операции.
4. Переключатель в `TeamSection`, пункт меню и просмотр базы для менеджера.
   Для свободной карточки — действие «Взять себе»; гонка назначения
   обрабатывается существующей атомарной проверкой назначения.

## Приёмка

- Админ и руководитель могут выдать и отозвать доступ менеджеру.
- Менеджер без доступа не читает базу и не берёт свободные лиды через прямые запросы.
- Менеджер с доступом читает свободную базу и берёт лид себе;
  не изменяет свободную карточку до назначения и не читает чужие назначенные лиды.
- Чужое рабочее пространство недоступно; два менеджера не получают один лид.
- Отзыв разрешения закрывает последующие запросы к базе, сохраняя собственные лиды.
- Узкие серверные и интерфейсные тесты, py_compile, typecheck, lint;
  Next.js build при изменении маршрутизации. Публикация — отдельное решение владельца.

## Проверено 12.10.2026

- 88 API-тестов прошли; 69 из них используют настоящий PostgreSQL,
  пропущенных тестов нет. Включены отзыв, права, изоляция пространств,
  две конкурирующие попытки назначения и существующие проверки выборок.
- 60 интерфейсных тестов прошли; typecheck и lint без ошибок;
  полная сборка Next.js завершилась успешно.
- Реальная миграция на отдельной временной базе: старые и новые пользователи
  получают false, существующие данные сохраняются, повторное применение,
  откат и повторное обновление работают. Временная база удалена после проверки.
- Из-за зависаний чтения установленных библиотек в Desktop тесты и сборка
  выполнены на точной копии исходников в `/tmp`, с зависимостями из исходных
  неизменённых lockfile. Файлы с ключами не копировались.
