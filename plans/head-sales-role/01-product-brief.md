# Product Brief — Руководитель отдела продаж: раздача базы и задачи команде

## Problem
Руководитель отдела продаж (роль `head`) видит панель команды, но не может распределить
базу лидов между менеджерами и не может поставить менеджеру задачу. Менеджеры сами
разбирают базу («Взять в работу» / спринт), а задачи существуют только внутри карточки
лида и достаются тому, кто владеет карточкой. Руководитель управляет «на словах» — вне CRM.

## Goal
Руководитель за ≤ 3 клика выдаёт конкретному менеджеру пачку лидов из базы (выделенные
или «N по фильтру») и ставит ему задачу — с лидом или без. Менеджер получает уведомление
и видит и лиды, и задачи у себя. Руководитель видит задачи всей команды с фильтром по
исполнителю и статусу.

## Target users
- `head` — руководитель отдела продаж (1–2 человека).
- `admin` — те же права плюс администрирование.
- `manager` — получатель лидов и задач; его собственный сценарий (взять лид себе, завести
  задачу себе) не меняется.

## User scenarios
1. Руководитель открывает «Базу лидов», ставит галочки на 5 карточках → «Выдать менеджеру»
   → выбирает Кирилла → подтверждает. Карточки уходят Кириллу, ему приходит одно
   уведомление «Вам выдано карточек: 5».
2. Руководитель фильтрует базу (город, сегмент, fit) → «Выдать N по фильтру» → 20 → Кириллу.
   Берутся только карточки из пула, чужие не трогаются; если пула не хватило — видно,
   сколько реально выдано.
3. Руководитель на странице «Задачи» нажимает «Новая задача» → текст, срок, исполнитель
   Кирилл, лид (необязательно) → сохранить. Кириллу приходит уведомление, задача появляется
   у него в «Мои».
4. Руководитель переключает вкладку «Команда», фильтрует по исполнителю и «просрочено».
5. Менеджер закрывает задачу, поставленную руководителем на его лид (раньше получал 403).

## Scope (оставшееся, после уже сделанного бэкенда)
- G2 — интерфейс выдачи на `/leads-pool`: чекбоксы в строках, панель выделения, модалка
  выдачи с двумя режимами и выбором менеджера, тост с результатом. Видно только `head`/`admin`.
- G4 — страница `/tasks`: вкладки «Мои» / «Поставлено мной» / «Команда» (последняя — только
  `head`/`admin`), фильтр по исполнителю и статусу, колонка «Кому», кнопка «Новая задача»
  с модалкой (текст, срок, исполнитель, необязательный лид). Закрытие/переоткрытие и правка —
  по id задачи, чтобы работали задачи без лида. Виджет задач на `/today` — не ломать.
- Верификация: 12 + 17 DB-тестов бэкенда (Postgres поставлен локально), `pnpm build`.

## Out of scope
- Выдача прав (смена ролей, приглашения) остаётся admin-only — пользователь уточнил, что
  «права» = «лиды из базы».
- Кнопка «Назначить» в карточке лида (`/leads/[id]`) — отложено, есть `transfer`.
- Подзадачи, повторяющиеся задачи, AI-подсказки в задачах (правило: задачи только ручные).
- Отдельный экран «Распределение базы».

## UX requirements
- Loading: таблица базы — существующий спиннер; модалка выдачи — кнопка «Выдать» в
  состоянии загрузки, повторный клик заблокирован.
- Empty: «Команда» без задач — Empty-состояние с подсказкой «Поставьте первую задачу».
- Error: тост с текстом ошибки бэкенда (`detail`), модалка не закрывается.
- Success: тост «Выдано N из M» / «Задача поставлена Кириллу»; список обновляется без
  перезагрузки.
- Disabled: «Выдать менеджеру» неактивна при нуле выделенных; «Новая задача» без текста
  или исполнителя — неактивна.
- Permission denied: менеджер не видит чекбоксов, панели выдачи и вкладки «Команда»;
  бэкенд всё равно отвечает 403.
- Mobile: чекбокс остаётся в первой ячейке; панель выделения — снизу экрана; модалки —
  на всю ширину.
- Keyboard: чекбоксы фокусируемы, Space переключает; клик по чекбоксу не открывает карточку;
  модалки — Escape закрывает (уже в `Modal`).
- Motion: без анимаций — инструмент на каждый день.

## Acceptance criteria
- Руководитель выделяет карточки галочками и выдаёт их менеджеру; менеджер видит их в
  «Воронке» и получает одно уведомление.
- Руководитель выдаёт «N по фильтру»; чужие карточки не затронуты; в тосте видно
  реальное количество.
- Менеджер не видит ни чекбоксов, ни панели выдачи.
- На `/tasks` руководитель видит вкладку «Команда», фильтрует по исполнителю и статусу;
  менеджер видит только «Мои» и «Поставлено мной».
- «Новая задача» создаёт задачу с исполнителем; без лида — тоже; исполнитель получает
  уведомление; задача видна ему в «Мои».
- Задача без лида закрывается и переоткрывается со страницы «Задачи» и виджета `/today`.
- `npm run typecheck`, `npm run lint`, `pnpm build` — зелёные; DB-тесты бэкенда — зелёные.

## Unknowns and assumptions
- Предположение: выдавать можно и самому себе (руководитель — тоже продавец). Бэкенд
  это допускает.
- Предположение: «Поставлено мной» показывает и закрытые задачи (с фильтром статуса).
- Проверено в коде: `Modal`, `Tabs`, `DataTable`, `Toast`, `useUsers` есть — новых
  зависимостей не нужно.
